# 子程序 MCP 调试通道

「子程序」是许愿码生成并开发的其他 App（比如你让 AI 写的某个工具类应用）。母程序与每个子程序之间有一条标准化的调试通道：子程序内置一个只监听本机回环地址的 MCP 服务，母程序经它查询子程序状态、拉取日志、执行自检——全程零特殊权限（不需要 root / Shizuku / adb），通信仅走 127.0.0.1 + 令牌校验，并拒绝外部来源请求。

## 这条通道能干什么

接入后，AI 在聊天里可以直接调用子程序的诊断工具（工具名形如 `mcp__subprogram-<端口>__<工具名>`）：

- **存活检查**：确认子程序调试通道在线。
- **状态查询**：内存占用、运行时长。
- **日志尾部**：拉取子程序应用日志的最后一段，排障第一手资料。
- **执行自检**：跑子程序内置的自检项，拿验收证据。
- **信息查询**：包名、版本。

除被动查询外还有一条主动上报：子程序按模板集成了崩溃上报后，崩溃时会在退出前向母程序发 signature 级广播，诊断页对应行显示「上次崩溃时间/累计次数」（详见[诊断与自测](/guide/diagnostics-selftest)）。

适合的场景：子程序没响应或行为异常时排障；开发完成后验收（让 AI 跑自检并回报证据）；随手看一眼子程序运行状态。

## 母程序如何生成并注入模板

新建工作区（即开始开发一个新子程序）时，母程序会自动完成两件事：

- 把调试通道模板写进项目的 `.aicode/templates/subprogram-mcp/`（含集成说明 README 与源码文件）。
- 在项目的 `.aicode/subprograms.json` 预写注册条目：名称、包名、端口与令牌（Token）已由母程序分配好。

你不需要手动准备任何端口或密钥。在子程序的工作区会话里让 AI「按 .aicode/templates/subprogram-mcp/README.md 集成调试通道」，AI 会把模板接入子程序工程（加依赖、复制文件、声明服务），完成后回填包名。也可以在「设置 → 诊断与自测」的子程序管理卡里，对不在线的子程序点「复制集成指令」，粘到子程序会话发送，效果相同。

集成完成后回到母程序诊断页点「检查」：在线即自动接入 MCP，聊天里立即可用。

## 排障：子程序没响应怎么办

按下面的顺序查，第一步就是权威判据：

1. **确认调试通道是否已启动**——用 `curl 127.0.0.1:<端口>` 探测子程序端口（可在母程序或子程序工作区的终端里执行）。有响应说明通道活着，问题在别处；无响应就是通道没起来，继续下一步。
2. **重装 APK 后通道不会自动恢复**：重装或覆盖安装子程序后，需要把子程序**冷启动一次**（从最近任务划掉再打开），或在母程序「设置 → 诊断与自测」点该子程序的「检查」——母程序会自动拉起它的前台服务。之后再试。
3. **确认令牌一致**：子程序侧配置的 Token 必须与母程序注册表里的一致，点列表行的「Token」可复制核对。
4. **确认集成完成**：子程序工程里是否真的集成了模板（依赖、文件、服务声明三样都不能少）。「复制集成指令」让子程序侧 AI 自查最省事。
5. **系统后台管控**：部分系统（如 MIUI）会杀后台的前台服务。给子程序授予自启动/后台运行权限，或保持它在前台时再检查。

通道在线但工具调用仍失败时，先在诊断页点「检查」重新接入 MCP，再回聊天页重试；仍失败把子程序的日志尾部发给 AI 分析。

## 管理入口

所有子程序的管理集中在「设置 → 诊断与自测」：体检、添加、检查、接入 MCP、复制 Token、删除，以及每行的在线状态。详见[诊断与自测](/guide/diagnostics-selftest)。
