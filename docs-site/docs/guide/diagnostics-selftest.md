# 诊断与自测

遇到问题需要排查，或想知道设备和容器环境到底长什么样时，「设置 → 诊断与自测」能一键生成环境报告、运行项目自测清单、管理子程序。整页能力**零特殊权限**：不依赖 root、Shizuku 或 adb，只读取本应用沙盒内与公共系统信息，数据不出设备（除非你主动分享）。

## 一键收集环境报告

点「一键收集」，稍等片刻会生成一份 Markdown 报告，覆盖四个层面：

- **设备层**：系统版本、屏幕、内存、存储、电池、网络状态。
- **权限层**：本应用已授的敏感权限与可选增强能力开关，方便核对「是不是少给了什么权限」。
- **应用层**：应用版本与各目录占用，顺带列出设备上由母程序生成的子程序安装态（版本、安装/更新时间）。
- **容器层**：Linux 发行版、工具链、各 CLI 引擎安装状态、容器目录占用与日志线索。

报告生成后有三个操作：

- **复制**：整份报告进剪贴板，可粘到会话里让 AI 分析。
- **分享**：走系统分享面板发给聊天工具或邮箱。
- **发到会话**：报告直接排入聊天输入框，回到聊天页发送，AI 就能基于报告帮你诊断。

同一排还有「清理旧日志」：自动删除今天之前的运行日志，日志目录过大时用它瘦身。

## 项目自测清单

每个项目都可以在自己的根目录放一份自测清单（`.aicode` 文件夹里的 `selftest.json`），内容是一组「名称 + 验证命令」——编译、测试、打包等能客观证明「做完了」的命令。清单通常由 AI 在项目初始化时生成，格式形如：

```json
{
  "project": "我的项目",
  "items": [
    { "name": "编译", "command": "./gradlew assembleDebug", "timeoutSec": 900 }
  ]
}
```

点「执行自测清单」，AI（或你手动触发）会逐项串行执行清单里的命令，输出一份带 ✅/❌ 标记的报告：每项显示通过与否、耗时与退出码，失败项附输出尾部片段，最后一行汇总「N / M 通过」。**存在未通过项时不得视为完成**——这也是 AI 交付前必须遵守的验收约定。

报告同样支持复制、分享、发到会话：发到会话后 AI 会接手处理未通过项。

清单缺失时页面会给出模板提示，让 AI 先补清单再执行。子程序侧也有同名机制，在子程序自己的页面触发即可。

## 子程序管理卡

「子程序」指由许愿码生成、开发的其他 App。母程序与它们之间靠一条内建的调试通道通信（仅走本机回环 + 令牌校验，零特殊权限），你可以在这里集中管理。

### 已安装子程序体检

点「体检子程序」，零权限列出设备上由母程序生成的子程序：包名、版本、安装/更新时间，同签名的会标注「（同签名）」。体检结果每行带「一键添加」：包名自动带出、端口与令牌自动分配、名称自动取包名末段，点一下就完成注册并立刻检查在线状态。已注册的显示「已注册」。

### 添加子程序

点「+ 添加子程序」，**只需填一个包名**：名称留空自动取包名末段，端口与令牌（Token）自动分配。保存后列表多一行，显示名称、包名、端口与在线状态。

每个子程序一行，提供四个操作：

- **检查**：探测子程序调试通道是否在线。在线会自动接入 MCP（已接入则不重复写入），随后聊天里就能直接调用子程序的诊断工具；不在线时提示先在子程序项目里集成调试通道，并提供「复制集成指令」——粘到该子程序的工作区会话发送，AI 就会按模板完成集成。
- **Token**：复制该子程序的令牌，子程序侧配置需要一致才能通信。
- **接入 MCP**：把子程序写进母程序的 MCP 配置。接入成功会提示工具前缀（形如 `mcp__subprogram-<端口>__`），在会话里即可调用。
- **删除**：移除注册条目，同时清掉已接入的 MCP 配置。

### 调用子程序工具

接入 MCP 后，回到聊天页直接对 AI 说，比如「看一下某子程序的日志」「跑一下某子程序的自检」，AI 会调用对应的诊断工具并回报结果。可用工具包括存活检查、内存与运行时长、日志尾部、内置自检、包名与版本信息等，以子程序侧实际集成的为准。

### 崩溃主动上报

子程序按模板集成了崩溃上报后（同签名才能生效），一旦崩溃会在退出前主动通知母程序；诊断页该子程序的行会显示「上次崩溃 N 分钟前（共 N 次）」，崩溃不再无声无息。没显示就是还没崩过，或子程序还没按模板安装上报器。

## 排错速查

- **报告没生成**：确认容器已启动；容器未就绪时容器层信息会跳过，其余层照常收集。
- **子程序一直「不在线」**：先确认子程序已按集成指令完成调试通道集成并启动；重装子程序后需将其冷启动一次（或在母程序侧点「检查」自动拉起它的前台服务）再试。
- **自测清单执行失败**：看报告里失败项的输出尾部，通常是命令本身报错；命令需能在容器里独立运行。
- **工具调用无响应**：先回诊断页点「检查」确认在线，再确认 MCP 已接入（列表行会显示工具前缀提示）。
