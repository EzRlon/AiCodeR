# 三种模式：Build / Plan / Auto

输入框下方有三个模式图标（构建 / 计划 / 自动），当前模式的图标高亮显示；点击未选中的图标直接切换（切换成功会有轻提示），点击当前模式的图标弹出说明层，每个模式带规则说明；处于计划或自动模式时，输入框上方常驻一条提示条，点右侧 × 一键退回构建模式。三种模式的区别是 AI 的**权限范围**。

## BUILD（构建模式）

默认模式，功能完整。AI 可以写文件、改代码、执行构建命令，但每次需要授权的操作都会弹窗询问。

日常开发建议使用此模式。被内置安全防护拦下的高危命令（如 `rm` 根目录），AI 可带 `elevate: true` 重试，转由你一次性授权（见[工具授权](/guide/permissions)）。

## PLAN（计划模式）

进入这个模式后，AI 的写操作权限会被底层直接拦截禁用（工具层拦截，而非仅靠提示词约束）。AI 只能读取代码、检索文件并构思方案，无法修改任何文件或执行写操作命令。

适合这些场景：

- 你还不确定怎么改，想先让 AI 探索代码库、给出方案。
- 改动涉及多个文件或架构决策，想先看计划再决定。
- 你只想问问题、了解现有实现，不希望它动手。

方案讨论清楚后切回 BUILD 再动手。

## AUTO（自动模式）

权限全放行。所有工具调用（写文件、执行命令、终端操作）自动批准，不弹任何授权窗。

::: danger 这个模式权限极大
只有灾难性删除（如 `rm` 根目录或系统目录）以及无法静态判定的疑似破坏性命令仍会被拦截，其余一律放行（可在「设置 → 工具授权」中开启「禁用安全拦截」取消这层兜底；AI 也可带 `elevate: true` 重试，届时会弹窗请你一次性授权）。适合你已清楚了解风险、希望 AI 全自动执行批量任务的场景。不熟悉的项目或不确定 AI 会执行什么操作时，不建议使用。
:::

## AI 也可主动请求切换

除了你手动点按钮，AI 也可以主动请求进入或退出 PLAN 模式，你在界面上一键批准即可。例如它在 PLAN 模式下完成方案后，会申请退出 PLAN 开始实施——退出后自动回到进入 PLAN 之前的模式。

有一个方向上的限制：**AUTO 模式只能由你手动进入**，AI 无法通过工具切进 AUTO。但反过来，处于 AUTO 模式时 AI 可以主动切到 PLAN——这是 AI 退出 AUTO 的唯一路径。

## 退出 PLAN 会回到进入前的模式

PLAN 是临时状态：进入 PLAN 时会记下当时的模式，退出时自动恢复。从 AUTO 进入 PLAN，计划做完退出后回到 AUTO；从 BUILD 进入 PLAN，退出后回到 BUILD。不会再一律落回 BUILD。

注意：退出 PLAN 仍需你在计划审查面板上批准（点「批准并实施」），批准后模式才真正恢复。

## 运行中也能切换

模式图标在 AI 正在执行任务时同样可用。你在 AI 执行任务的过程中切换模式，它会**当轮立即生效**：AI 会收到一条模式切换通知，手头任务从那一刻起按新模式处理（例如你中途切到 AUTO，后续操作就不再逐次弹窗；切到 PLAN，后续写操作会被拦截），无需等待本轮结束。

## 长按模式图标：创建定时任务

模式图标还带时间维度：**长按任意一个图标**在 Build 下弹出「定时任务」创建面板（给 AI 一条指令，到点自动执行），在 Plan 下弹出「定时 Plan」入口（先备好完整计划，排期后到点无人值守自主施工）。顶栏「+」长按有同样的入口；创建后的排期与启停在「设置 → 定时任务」管理。详见[能力地图](/guide/capabilities)。

## 外部引擎（Claude Code / Codex / OpenCode）

使用外部引擎的会话，模式菜单直接列出**该引擎自己的原生档位**（每个引擎有多少种就显示多少种），而不是把上面三档语义压扁后投影。各引擎的原生档位如下：

| 引擎 | 原生档位（默认加粗） | 权限含义 |
| --- | --- | --- |
| Claude Code | **默认询问 (manual)** / 自动接受编辑 (acceptEdits) / 计划 (plan) / 自动判定 (auto) / 不询问 (dontAsk) / 全部放行 (bypassPermissions) | 对应 CLI 的 `--permission-mode` 六个取值 |
| Codex | 只读 (read-only) / **工作区可写 (workspace-write)** / 完全访问 (danger-full-access) | 对应 CLI 的 `-s` 沙箱三个取值 |
| OpenCode | **构建 (build)** / 构建 + 自动批准 (build+auto) / 计划 (plan) / 计划 + 自动批准 (plan+auto) | `--agent build\|plan` 身份 + `--auto` 放行开关的组合 |

切换引擎时，会话里记录的原生档位会重置为新引擎的默认档，不会把旧引擎的档位带过去越权。

注意三点：

- **切换在下一回合生效**：外部引擎是独立 CLI 进程，回合进行中切换模式不会打断当前进程，下一条消息开始时按新模式运行。
- **Codex 没有逐次审批**：它的非交互模式不支持逐次确认，所以「工作区可写」档位下工作区内的命令会自动执行、区外被拦截。这是引擎能力限制。
- **Claude Code 的「全部放行」在容器里需要逃生开关**：容器内 CLI 以 root 运行，`bypassPermissions` 会被 CLI 直接拒绝退出，应用已自动补上 `IS_SANDBOX=1` 让其正常运行。
