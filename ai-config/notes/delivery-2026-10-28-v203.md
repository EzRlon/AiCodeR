## 版本线决策

- v2.1.0（versionCode 93，2026-10-26 发布）之后累计 108 个提交，含三引擎接入、记忆图谱 v2、标注统一画布、用户脚本、定时任务、存储推荐清理等成体系功能，按 SemVer 升 minor 到 **2.2.0**。
- tag 必须为 `vX.Y.Z` 形式：App 内「检查更新」用 `parseVersionTag` 取 tag 去 `v` 后按 SemVer 与当前 versionName 比较；且 APK 的 versionName 由 `git describe` 从 tag 生成。tag 与 versionName 不一致会导致装完仍反复提示有更新。

## 与 GitHub Releases 的关系

用户反馈「仓库还是两天前的 v2.1.0」的原因：此前只推送了 `dev` 分支，未打 tag、未建 Release。Release 列表由 tag 驱动，因此停留在 v2.1.0。

本次流程：提交发布说明 → 打 annotated tag `v2.2.0` → 从 tag 提交构建 → 推 tag 与 dev → `gh release create` 上传 APK 并标记 latest。

## CI 处置

`.github/workflows/android-release.yml` 在 push `v*` tag 时自动三架构构建并自动发 Release，但仓库**未配置任何 Actions Secrets**（`gh secret list` 为空），缺 keystore 必然失败：v2.1.0 触发的运行（run 40395962622）跑了 6 小时 37 分后被取消。

因此本次 `gh workflow disable "Android Release"` 后改为本地构建手动发版。恢复方式：配齐 `AICODE_KEYSTORE_BASE64` / `AICODE_KEYSTORE_PASSWORD` / `AICODE_KEY_ALIAS` / `AICODE_KEY_PASSWORD` 四个 secret，再 `gh workflow enable "Android Release"`。
