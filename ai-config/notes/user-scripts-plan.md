# 用户脚本系统规划（2026-10-22 立项，方案待用户确认后实施）

> 目标：①App 内置「脚本」能力（容器内固化可复用的自动化）；②在线商店新增「脚本」页与
> 技能/MCP/专家团完全对齐（含自动汉化、持久缓存）；③定时任务支持运行脚本与调用已集成插件。

## 一、脚本是什么（本体内置）

- **形态**：容器内可执行单元——`.sh` / Python / Node 片段或文件，存 `~/.aicode/scripts/`
  （随备份/迁移走，与技能/MCP 同策略）。
- **脚本页**（侧栏或工具页入口）：列表卡（名称·语言图标·描述·上次运行时间·来源）＋
  新建 / 编辑（复用现有文件编辑器）/ 运行（输出内联展示，长输出折叠）/ 删除 / 固化。
- **「固化脚本」**：用户或 AI 把一段验证过的自动化存为命名脚本，成为可复用资产——
  这是「越用越聪明」的项目资产层（随项目/全局积累）。
- **运行安全**：走现有权限引擎与守夜守护规则（无人值守时危险命令静默拒绝＋改写引导）；
  脚本执行全部在容器内，不触碰本体权限面。
- **AI 集成**：新增 `run_script` 工具（列脚本/按名运行/返回输出）＋能力感知登记——
  AI 能把「用户口头描述的自动化」沉淀为固化脚本，下次直接调。

## 二、在线商店「脚本」页（第四个 tab，完全对齐现有框架）

| 对齐点 | 复用机制 |
|---|---|
| 目录缓存 | StoreCatalogCache 加 SCRIPT_FILE，秒出＋后台刷新 |
| 自动汉化 | 翻译管线加 SCRIPT 类型（sourceHash 失效重翻；名称双语展示保原文可搜） |
| 市场源 | GitHub 精选仓库（marketplace.json 模式，gh-proxy 链路），一期 curated 少而精 |
| 安装 | 下载到 ~/.aicode/scripts/，**必须过安全层扫描**（与商店安全层批次一共享 InstallScanService，脚本属于「进容器的可执行文本」，风险等级更高，扫描规则含危险命令特征） |
| 版本/更新 | 随安全层批次二的 installed-registry 一并支持 |

## 三、定时任务增强

- 任务动作新增「**运行脚本**」类型：选已装脚本＋现有 cron 规则引擎，跑完可选通知
  （成功静默/失败必报，输出截断入库可回看）。
- **调用已集成插件**：脚本运行在容器内 → 天然可调已装的 CLI/MCP 服务端（如 rea、multillm）；
  另提供「脚本＋AI」组合动作：脚本产出 → 交给当前会话模型做摘要/判断（复用现有定时任务的
  模型链路）。
- 无人值守安全：定时脚本同样过守夜守护与权限引擎，与 scheduled-auth 纪律一致。

## 四、分期

1. **一期（本体内置）**：脚本页（增删改运行）＋ run_script 工具＋定时任务「运行脚本」动作＋能力感知。
2. **二期（商店脚本 tab）**：市场源＋目录缓存＋自动汉化＋安全扫描对齐（依赖安全层批次一先落）。

## 五、明确不做

- 脚本不跑在本体进程内（不做 JS 引擎/插件宿主），一律容器内执行——安全边界最简、
  复用容器既有语言环境。
- 一期不做脚本市场（先让「固化脚本」跑通，市场随二期进商店）。

## 六、验收要点

- 固化一个「清理容器缓存」脚本 → 手动运行成功 → 挂每日定时 → 无人值守触发且有记录。
- 商店脚本条目：英文描述自动双语展示、原文可搜、缓存后重进不重翻。
- AI 被要求「把刚才那串命令固化成脚本」→ 产出脚本并可运行。
