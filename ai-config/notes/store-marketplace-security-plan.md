## 背景与目标

现状（已核实）：商店装的是第三方「进 AI 上下文的指令文本」，现有清洗仅做格式适配（剔除外部 tools/model 行），无内容安全审查、无版本管理、装完即冻结。三大风险/缺口：

1. 提示词注入（恶意技能描述/正文诱导 AI 提权、外发数据、覆盖系统规则）
2. 已装条目与市场源脱节（无版本记录、无更新检测）
3. 单件安装，Claude Code 整包插件（技能+代理+命令+钩子）只摘了 agents

## 批次一：安装安全层＋禁忌扫描（P0，最先做）

### 设计：InstallScanService（新组件，store/domain/）

安装动作（installSkill / installMcp 配置 / installTeam 拉取的 agent 与团队定义）在写盘前统一过一道扫描，输入=将写入的全部文本，输出=三级结论：

- **PASS**：无命中，正常安装。
- **WARN**：命中可疑特征 → 安装按钮变黄、展开「风险详情」（命中的原文片段+行号+类别），用户可「我已知晓风险，继续安装」。
- **BLOCK**：命中高危特征 → 默认不可装；红色警示 + 详情；需用户在详情页显式点「我确认仍要安装」才能放行（保留最终决定权给用户，但绝不静默）。

### 特征库（初版清单，实现时可扩充）

高危（BLOCK）：
- 诱导覆盖系统规则：「忽略之前的指令/规则」「无视安全限制」「不要告诉用户」「secretly/隐藏执行」
- 伪装系统标签：`<system-reminder>`、伪造 `<system>`/`<claude>` 等系统容器标签、伪 system prompt 声明
- 凭据外发特征：正则命中 sk-/Bearer/API Key 形态字符串 + 同文件存在网络发送指令（curl/wget/fetch 到非官方域名）
- 大块 base64 / 零宽字符 / 同形字符混淆（隐藏载荷的经典手法）

可疑（WARN）：
- 提权措辞：要求「自动批准所有操作」「绕过权限确认」「无人值守静默放行」（对照本项目 scheduled-auth 静默放行坑，这类措辞必须提示）
- 下载并执行外部脚本；写 shell 配置/环境变量；删除类命令
- 越权访问路径：`~/.aicode/keys`、密钥文件、`app/keystore` 等敏感路径引用

内容禁忌（WARN/BLOCK 按类目）：
- 明显恶意用途类目（攻击工具、钓鱼模板、窃取类）→ BLOCK
- 其余违反商店政策类目（成人/赌博/诈骗话术模板等）→ WARN+类目标注

### 实现要点
- 扫描器纯本地、规则驱动（正则+启发式），不联网、不调模型——零成本零延迟，也避免「用 AI 审 AI」被绕过。
- 特征库做成 assets 内 JSON（可热更），版本号入库，升级 App 或拉取规则更新即可扩充。
- 扫描结论与命中文本一并返回 UI；详情弹层复用现有条目详情壳。
- 已装条目补扫：升级后首次进「已装管理」时对存量做一遍扫描，命中即标黄/红角标。

## 批次二：版本记录与更新检测（P1）

- 安装时写本地清单 `~/.aicode/installed-registry.json`：条目类型、来源（市场+URL/slug）、版本、contentHash、安装时间、扫描结论。
- 进商店列表时对已装条目做源比对（contentHash 或 version 不同 → 「有更新」角标）。
- 一键更新 = 重新拉取 → 过安全扫描 → 覆盖写盘（旧版留 .bak 一份，可回退）。
- 注意：比对要节流（每次进店只比对当前 tab 可见条目，不整库扫）。

## 批次三（中期）：整包插件安装 + 精选推荐位

- 整包：安装器升级为「插件包」粒度（技能+代理+命令一次装、统一启停）；wshobson 市场不再只摘 agents。
- 精选位：assets 内置 curated 清单（实测适配过的条目），列表置顶「已验证」徽标，人工策展替代自建市场运营。

## 明确不做

- 不自建托管市场（重资产，现生态够用）。
- 不做语义/向量检索（设备算力不允许，FTS 关键词+引导已够用）。

## 验收要点（届时）

- 注入样本集：准备 5-8 个恶意样本（伪装 system 标签、诱导提权、密钥外发、base64 藏载）逐个过扫描，BLOCK/WARN 命中率 100%。
- 误报抽查：官方示例技能 20 条扫描，WARN 误报率可接受（目标 <10%）。
- 更新链路：改市场源内容 → 商店出现更新角标 → 一键更新成功且旧版可回退。
