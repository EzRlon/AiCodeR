## 一、待施工清单（评审后按批归并）

### B1 修复与微调（P0，无依赖，最先做）
1. **底栏失效 bug 修复**：任务进度线框触摸层独吞点击——拆「纯绘制层 + 节点小热点」（根因已定）。
2. **语音 / + 按钮位置对调**（输入区右下角）。
3. **保存按钮改小图标**：6 个编辑页顶栏（记忆/提示词/技能/子代理/凭据/定时任务）文字「保存」→ 小图标（对勾+无障碍描述）；对话框内按钮不动。

### B2 视觉工具箱（P1，输入区体验核心）
4. **视觉四件套**：拍照 / 相册 / OCR / 扫码（ML Kit 离线打包版）；扫描自研（CameraX+裁剪）——结果全部可入会话。
5. **入口分区（不挤）**：输入区「+」菜单分组【添加/识别/实时/更多】→ 全屏「**AI 工具箱**」（分类网格：视觉/语音/开发/数据）；设置侧新设「**工具与能力**」分组（工具授权/工具箱/工作流/编队归拢）。
6. **工具授权页改版**：新增「内置工具」区（图标+名称+一行简介+**折叠说明**：是什么/能干什么/所需权限/安全提示，中英双语）；权限说明组件（权限名+用途+一键引导）。
7. **新工具集成（4 个）**：JS 沙箱计算（QuickJS）、剪贴板读写（写为主、读需显式）、语音朗读（TTS 工具化）、图表展示（聊天内折线/柱/散点卡片）。
8. **悬浮球（跨应用推进项目）**：系统悬浮窗（`SYSTEM_ALERT_WINDOW`，设置开关默认关+引导授权）——边缘可拖小球，球面显示任务状态（运行中环/等待确认呼吸/失败红点）；点开迷你面板：当前任务进度、快速输入＋按住说话、**等待确认直达处理**（权限/提问不切 App 直接答）、快捷排（截屏标注/实时翻译/打开会话）、**朗读控制**（吸收 Rikka 同款部分）；前台服务保活联动；不读屏、不模拟操作、无无障碍。实现选型：FloatingX 3.0（Apache-2.0，Rikka 同源已验证；备选 EasyFloat），面板内对话框用系统级 Dialog（参考 compose-floating-window 经验）。

### B3 实时语音翻译体系（P1，你点名的重点）
8. 流式转写（sherpa-onnx 流式 zipformer + VAD，端侧离线）。
9. 句子级流式翻译（你的模型；**多目标语言**+源语言自动识别；自动去噪）。
10. 顶部悬浮窗（App 内、双语双行滚动）+ **实时文字转写进会话**（复用外部文本入草稿通道）。
11. **译文朗读**（Kokoro-82M 多音色：103 音色可选+试听+系统 TTS 备选；全离线免费）——播放控制集成进悬浮球（见 B2-8），并吸收 Rikka 的 TTS 悬浮控制形态。
12. 音色角色分离：自动分辨发言人（默认「发言人 A/B/C」可改名）+ 声纹库记忆；角色→不同朗读音色。
13. 会议总结（LLM 分块摘要，复用现有机制）。

### B4 开发与终端增强（P1-P2）
14. **终端 UI 重设计**：会话标签横滑条、额外键条升级（Ctrl/Esc/Tab/方向/管道，可自定义）、命令面板（历史模糊搜索）、终端内搜索、选中即复制；与 AI 协作（选中→发 AI 解释；「让 AI 执行」）。
15. **终端工具市场 + 设备桥**：Alpine 精选工具一键安装（tmux/fzf/bat/eza/rg/fd/jq/httpie/rclone/micro…，官方签名源）；设备桥白名单命令（notify/clipboard/open，文件 IPC 安全通道）。
16. **文件管理增强**：P1=git 变更标记/长按菜单（复制路径·终端打开·问 AI）/文件大小与详情；P2=多选批量、批量重命名（模板）、压缩解压（zip）、名称过滤。
    - **HTTP 远程管理（MT 同款业务逻辑，用户点名）**：左侧栏文件 Tab 顶栏入口→面板（开关/监听地址+二维码/访问口令/只读·读写模式）；局域网网页端：浏览/上传/下载/新建/重命名/删除（默认只读）；**只暴露当前工作区**、默认关闭、口令必填（参照 MT v2.26.9 的 Bearer 令牌方向；避开其「时间戳鉴权易受时钟不一致」的坑）。技术选型：**NanoHTTPD**（轻量，相对 Ktor server 的几 MB 重依赖；自研裸 socket 不做）+ 内嵌静态页（无前端框架；网页内适配深浅色）。与 Rikka web-access 差异：我们只做文件管理段，不做网页聊天。
17. **工作流 P1（声明式）**：`.aicode/workflows/<name>.md`（步骤=「对 AI 指令」+变量）；执行器顺序逐步跑（可插人工确认）；`/workflow` 入口；运行记录存档；预置示例（主题研究/周报/仓库体检）。

### B5 平台与生态（P2，可多批）
18. **在线商店**（技能→claudemarket.ai 开放 API；MCP→官方 Registry；编队→从链接导入；三段式隔离/统一模型/六排序/双语详情）。设计存档：`notes/online-store-plan.md`。
19. **记忆库功能**（仅画像域）：导入导出（JSON）、问询式补充（文字/语音）、画像归纳与冲突检测。
20. **会话历史归档体系**：压缩时增量导出 `.aicode/history/`、index.md（零额外 token 生成）、发送前硬保险丝、AI 检索指引（P2 专用工具+存储空间联动）。
21. **RikkaHub 吸收项**：搜索服务多源（Exa/Tavily 等，★）、AI 翻译、消息分支、数据恢复页、技能页搜索。
22. **工作流 P2**：Compose 节点画布（LLM/条件/循环/工具/确认）、定时触发接入（复用定时任务模块）、导入导出分享。
23. **定时自主施工（保活版）**：定时触发 AI 会话任务 + 保活联动（设计细化后实施）。
24. 远期池：工作流市场（挂商店）、端侧翻译模型、词级同传、文档扫描透视增强。

## 二、依赖与顺序（裁决）

- **B1 无依赖、立即做**（用户痛点最直接）。
- **B2 先行**：其「入口分区」是 B3 悬浮窗与后续一切新功能的**归属框架**（先立框架再塞功能，避免「挤在一起」）；其「工具授权改版+权限说明」是新增一切工具/权限的统一载体；AndroidManifest 权限（相机等）在本批一次到位。
- **B3 依赖 B2 的入口与权限载体**；朗读模型下载机制与「模型管理」联动。
- **B4 独立可并行**（终端/文件/工作流互不依赖；工作流 P1 依赖既有任务引擎）。
- **B5 顺序**：商店（与工作流市场联动）→ 记忆库 → 历史归档 → 吸收项 → 工作流 P2 → 定时施工。
- **交叉裁决**：①历史归档与「交接提醒」并存联动（前者=同会话可查，后者=开新会话），不冲突；②商店/工作流/记忆库均按 MVP 范围先落可用形态，防大而无当；③每批完成后跑统一标准（编译+qa+真机清单）。

## 三、验收标准（每批统一）

- 编译全绿；独立 qa 审查通过（无阻断）；该批功能在真机清单上逐项可用；中英双语与深浅双主题适配；文档同步（docs-site）。
- 真机清单在每批开工时按批生成（含：功能可见性、核心路径、异常提示）。

## 四、风险与说明

- 未知量最大的是 B3（端侧模型体积/性能）与 B5-18（第三方站点可用性）——均在设计中已留降级预案（系统 TTS 备选、HTML 抓取后备、失败不阻塞）。
- **权限新增**：B2/B3 的相机、麦克风（已有）、通知（已有）；**悬浮球需 `SYSTEM_ALERT_WINDOW`**——属用户明确要求的功能性例外（原设计哲学「不申请额外系统权限」经用户确认例外）；默认关闭、可随时撤销、不读屏不模拟操作、无无障碍服务。日历/屏幕时间类敏感权限**不做**。
