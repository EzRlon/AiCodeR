## 三、待办（按优先级）

### P0 · 外部引擎子代理不建子会话（F7，已诊断未实现）
**根因（已核实）**：`newSubSessionEntity` / `upsertSession` 全仓仅 2 处调用，都在内置引擎 `TaskTool.kt:237,257`。`ClaudeCodeBridge` / `CodexBridge` / `OpenCodeBridge` / `AbstractCliBridge` 中 `newSubSessionEntity`、`upsertSession`、`SubAgentEvent` **全部 0 命中**——只把 `Task` 渲染成一条工具行。

**方案**：桥解析到 `Task`/`Agent` 调用时建子会话（`parentId`=当前会话、`subagentType`=成员名）→ 产出落该子会话 → 结束发 `SubAgentEvent(COMPLETED/FAILED)`。
**风险**：CLI 子代理在引擎进程内部，只能拿到「调用参数 + 最终 tool_result」，子会话内容是「任务描述 + 最终报告」，非完整过程。按 CLAUDE.md 属引擎桥敏感面，建议开分支 + 发 RC。

**已知坑**：
- 构建目录被并发清理 → KSP 报「文件不存在」：`rm -rf app/build/generated/ksp app/build/kotlin` 后重跑
- 同一时段可能有另一路会话跑 gradle（互相 `--stop`），失败先排除环境争抢

- 用脚本改 Kotlin 文件时注意：插入函数容易「抢走」相邻的 `@Composable` 注解或漏 import（本轮出现过两次），改完必须编译确认

## 八、agentTermination 排查（F12，结论：非 App 缺陷）

### 已核实的事实

| 检查 | 结果 |
| --- | --- |
| 全仓精确 grep `agentTermination`（排除 `build/`、`.git/`） | **仅本文件命中**，源码 0 处 |
| `SubAgentEventType` 全部成员 | `SPAWNED/COMPLETED/FAILED/STOPPED/DELETED/MESSAGE_FROM_PARENT/MESSAGE_FROM_SUB`，**无此类型** |
| Claude 桥事件分支 | 只认 `stream_event/assistant/user/system/result`，未知 `type` → `else -> emptyList()`，**静默丢弃、不打印** |
| App 内唯一的 `type=` 日志 | `SubAgentEventBus.kt:160`、`AIAgentViewModel.kt:1790`，值域是上面那个枚举 |

结论：**该字符串不产生于 AiCodeR App**。它属会话运行层（harness）的 agent 生命周期事件；本轮会话多次中断（后台任务被 teardown、上下文截断）导致终止信号在末尾重复出现。

### 若要在新会话确认（按用户看到的位置分流）

1. **出现在聊天记录末尾** → 是运行层会话事件，与 App 无关；无需修代码。
2. **出现在 App 日志** → `grep -rn "agentTermination" ~/.aicode/ /data/data/com.aicoder/files/ 2>/dev/null`（或在「设置 → 日志」里搜）。有命中说明是外部引擎 CLI 原样透传。
3. **出现在终端标签** → 是 Claude Code / Codex CLI 自身的 stdout，App 只是透传渲染。

### 条件式修复方案（仅当确认出现在 App UI 或日志时执行）

| # | 修复 | 落点 |
