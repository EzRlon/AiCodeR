## 二、下沉设计（A → App 内置）

1. **内置技能**：`assets/skills/code-intel/`（适配 App 容器：同 musl 环境，坑位说明原样适用；
   路径改为 App 容器内约定路径；中英双语 token 纪律）。
2. **场景脚本扩展**：`assets/aicode/lib/scenarios/` 新增 `codeintel.sh`（幂等）：
   `apk add ctags` ＋ `apk add gcompat` ＋ npm 装 @ast-grep/cli-linux-arm64-gnu（--ignore-scripts --force，
   走 npmmirror）＋ 软链 ast-grep；失败降级不阻塞（ctags 先行可用，ast-grep 可后补）。
3. **工具脚本随 App 释放**：`assets/aicode/lib/tools/repo-map.sh`、`callchain.sh` → 容器内可执行路径。
4. **索引维护自动化（一期用提示词引导）**：code-intel 技能写明「大改后重建索引」；二期可在
   检测到批次改动落盘后由 App 自动触发重建（避免依赖 AI 自觉）。
5. **能力感知两件套**：capabilities.md（场景→能力）＋ 65-capabilities.md 速查行
   （「大项目里找功能实现/调用链/类结构 → code-intel 四件套」）。

## 三、「越用越聪明」累积机制（用户重点诉求）

| 累积层 | 机制 | 现状 |
|---|---|---|
| 项目结构层 | tags/repo-map 随项目存续持久化，改动后重建——项目越老索引越全，AI 摸底成本趋近于零 | 下沉后达成 |
| 历史经验层 | recall＋FTS4 随会话归档自动变厚；压缩只摘要原文永在 | ✅ 已有 |
| 决策记忆层 | memory 两库（用户画像/踩坑坑）＋记忆图谱（v86）——踩坑必须验证后入库，防污染 | ✅ 已有 |
| 行为规范层 | 审查路由/发送纪律等强制规则沉淀进项目规则与内置提示词，跨会话稳定生效 | ✅ 已有（本批加审查路由） |
| 词汇缓存层 | 商店翻译缓存持久化（filesDir），汉化一次永久生效 | ✅ 本批达成 |
| 审查知识层 | qa/optimizer 报告的处置结论沉淀进 notes，后续同类问题直接引用；self-improve 模式把「被纠正的行为」写回技能/提示词 | ✅ 骨架已有，随审查路由常态化变厚 |
| 工具预算层 | MCP enabledTools 白名单（REA 方案内设计）：控制 207 工具级 token 爆炸，按场景只挂需要的 | 规划中（随 REA 落地） |

设计原则：**每一层都只增不删、可回溯、有验证门槛**（踩坑须验证、审查须处置），避免「越用越糊涂」。
