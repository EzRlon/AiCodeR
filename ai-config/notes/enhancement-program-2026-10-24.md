## 目标一补充（2026-10-24 二轮调研）：提示词缓存友好装配

- 1.5 **提示词缓存友好布局（append-only）**：静态内容固定前置（顺序 tools→system→messages，与 Anthropic 缓存层级一致），动态内容只追加尾部，会话中段不改工具表/系统提示词（会击穿供应商 KV 缓存）；统计缓存命中率入 Token 仪表盘。依据：Anthropic 官方（缓存读成本降至 1/10、长提示延迟降 85%）、DeepSeek 磁盘缓存默认开启（前缀命中免费重用）、Claude Code 实践（append-only 会话天然高命中）。
- **合并施工提示**：1.5 与「按模型分档压缩」改的是同一段消息装配代码，**合并为一个施工项一次改完**，避免重复改动同一处。
- **两条硬约束（评审采纳）**：①压缩只在「追加新消息前」的边界执行一次，执行后继续 append-only；②同一会话内**不因切换模型而二次改写历史**，模型切换只影响后续新增消息的装配策略。另标记 cache-invalidating 事件（压缩/工具结果清理/模型切换）供仪表盘统计命中率。

## 第三轮补充建议（2026-10-24，基于评审后的空档分析；均为新增、不与既有项重复）

1. **1.6 子代理任务书模板库**：现有 qa/optimizer/explore 定义各写一遍上下文成本高。抽一份「任务书模板」（目标/范围文件/上下文预算/期望输出格式/硬约束），派发时填槽即可 → 派发更快、漏项更少。与 1.1（Harness 借鉴）不重复：那是架构借鉴，这是操作模板。
2. **1.7 失败事件埋点与看板（支撑 1.3 的运行时裁判）**：定义三个最小事件——①意图纠正（用户重述/改口/重发）②任务失败（工具报错/权限阻塞）③编译失败。把它们接入已有 Token 统计看板（同 Vico 趋势图组件），成为「更准」的长期量化依据。1.3 评测集是离线护栏，本项是线上指标，两者互补不重叠。
3. **1.8 agent 产出自检清单**：现有 qa 纪律只审代码，不审「建议类输出」。对安全/性能/配置类结论，交付前强制附「影响范围 + 回退方式 + 风险提示」三要素（写入通信类提示词）→ 直接降低“建议看错”的事故率。
4. **3.4 工具结果压缩的保真规则**：现有压缩只保证不丢上下文，不保证不丢语义。新增硬规则——压缩时必须保留**语义锚点**（退出码、错误行、关键字段、失败原因），而非纯截断 → 压缩后仍可判错，与 1.5 的装配布局属不同层（内容质量 vs 布局），不冲突。
5. **4.5 预算感知与快准模式（并入 4.2 不另立项）**：每轮显示预估成本/延迟（用 4.1 的画像数据）；提供「快/准」开关——简单任务自动用快模型+精简上下文，复杂任务才升级。实现上是 4.2 的策略参数，不是第二套路由。
6. **2.4 构建排队锁（防双会话污染）**：新增 `tools/build-with-lock.sh`，用锁文件保证同一时间只有一次构建（双会话并行=KSP 缓存污染，已验证坑，且本轮已实际发生）。同时提一键回滚脚本（daemon/in-process、jetifier 开/关可秒退）→ 配置类优化可随时撤销。
7. **2.5 构建耗时可观测（并入 2.2 自检脚本）**：每次构建把耗时写入趋势记录（解析 Gradle profile/构建报告），形成「本机编译耗时曲线」——以后任何构建改造都有历史曲线可对账，而不是只靠单次数字。
