## 本包修复内容（5 条用户反馈）

### 反馈 1 + 4：主题切换后文字与背景同色、看不见（含"触摸后才显示"）

**根因**（用 `javap` 解包 material3 1.4.0 字节码核实，非推测）：

1. `androidx.compose.material3.MaterialTheme` **不提供** `LocalContentColor` —— 它只 provide
   ColorScheme / Typography / Shapes / MotionScheme。
2. `LocalContentColor` 的根默认值是 **`Color.Black`**（`ContentColorKt$LocalContentColor$1` 返回 `Color.Black`）。
3. `contentColorFor(ColorScheme, color)` 只逐项比对 ColorScheme **标准槽位**，查不到返回 `Color.Unspecified`；
   composable 版 `contentColorFor(color)`（Surface/Scaffold 实际调用）在槽位匹配失败时**回退读父级**
   `LocalContentColor`。
4. 本项目大量容器传**语义色**（`pageBackground` / `cardSurface` / `mutedSurface`）或 **`Color.Transparent`**，
   槽位匹配必然失败 → 一路回退到根默认的**黑色** → 深色主题下与背景同色，整块文字不可见。
5. `Text` 直接读 `LocalContentColor.current`，不做二次回退，Unspecified 最终渲染成黑色。

另外两处 `graphicsLayer { alpha }` 常驻在整棵 App 子树/悬浮层外层，形成离屏图层缓存，
主题切换时不重绘 —— 这是"手指触摸相关区域才显示"的来源。

**修法**：

- `AIEditorTheme.kt`：根层 `CompositionLocalProvider(LocalContentColor provides onBackground)`（关键修复，
  整条继承链最终回退到这里）
- `ChatDrawer.kt`：侧栏面板包 `CompositionLocalProvider(LocalContentColor provides onBackground)`
- `SettingsGroupComponents.kt`：`SettingsGroup` / `LazyGroupItem`（自绘卡片背景）显式给文字色
- 46 个文件、约 85 处 `Surface`/`Scaffold`（语义色或透明底）补 `contentColor`，语义按底色映射：
  `cardSurface→onSurface`、`pageBackground→onBackground`、`mutedSurface→onSurfaceVariant`、
  `warningContainer→onWarningContainer`
- `ReaWorkbenchScreen.kt`：顶栏补 `titleContentColor`
- `MainActivity.kt` / `AIChatPanel.kt`：淡入/滚动弱化动画结束后**摘除** `graphicsLayer`；
  用布尔状态驱动挂载（动画值只在 lambda 内读），避免组合期每帧重组

### 反馈 2：Git 界面底部出现看不到内容的"白条"

**根因**：M3 `Snackbar` 默认 `containerColor` 取 `SnackbarTokens.ContainerColor = inverseSurface`，
`contentColor = inverseOnSurface`；而本项目 `AppThemePreset` 里 `inverseSurface = seed.onSurface`（近黑）、
`inverseOnSurface = seed.surface`，**反色关系不成立** → 浅色页面里成了一条白底看不到字的条，
且 Snackbar 贴在 Scaffold 底部正好盖住悬浮 tab 栏，默认 4 秒后才消失（用户感知"好几秒才恢复"）。

**修法**：

- 容器未就绪改为**常驻 warning 横幅**（`GitScreen.ContainerNotReadyBanner`），不自动消失、不遮底栏；
  回到页面时 `LifecycleResumeEffect` 重查，容器就绪后自动消失（qa P1-1）
- 未就绪时隐藏底部 tab 栏（避免"tab 可点却无内容"的误导）
- Snackbar 显式绑定主题色（`mutedSurface` / `onSurfaceVariant`）并上移 74dp 避开底栏

### 反馈 3：浏览器打开网页后 3 秒内弹错误

**根因**：无协议头输入（如 `www.baidu.com`）先试 `https`，失败时 `onReceivedError` 立刻把错误写进
`tab.error` 并显示；随后回退 `http` 成功加载，但错误仍挂在 tab 上 → 用户看到"网页已打开却弹错误"。

**修法**（`BrowserManager.kt`）：

- 新增 `probing` 标记：探测阶段（https 未果、即将回退 http）的失败**不写到界面**
- 回退 http 也失败时异常上抛，由界面错误气泡展示（不静默成空白页）

### 反馈 5：存储空间应统计 agent 交付物并标注、补三个新引擎

先核实**重叠**：交付物原本分散在「工作区」（构建产物）与「AI 配置与产物」（tool-output / 识图 /
生成图片）两处，因此**不重复计数**，改为在既有分类的明细上增强：

- 明细新增 `StorageSafety` 处置标注：**可安全删除 / 已过期可删 / 删后影响历史查看 / 运行必需请保留**
- 「AI 配置与产物」按 mtime 给出过期判定（30 天阈值，与清理推荐引擎同源）
- 聊天附件标「删后影响历史查看」（用户上传的原始文件，不可恢复）
- 新增「智能体引擎」明细：三个 CLI 引擎（Claude Code / Codex / OpenCode）的全局包与会话目录占用
  （实测合计约 1.1 GB），与容器缓存 du **合并为一条命令**，避免 PRoot 全树遍历翻倍

**qa P1 处置**：

**性能审查（optimizer）P1 处置**：

5. **AIChatPanel 输入框双重淡出（本次修复引入的新回归）** → 外层统一 alpha 图层与 `ChatInputBar`
   自带的 `contentAlpha` 叠加（0.4×0.4≈0.16，输入框几乎不可见），且把必须不透明的渐变蒙版
   一起淡掉（0.39，滚动时消息文字透出输入框区）。改为逐面板套 `floatingFadeModifier`
   （StatusBanner + 4 个 AnimatedVisibility），输入框排除在外；延迟放宽到 240ms
6. **Git 首进双刷新** → `refresh()` 只拦 `busy` 不拦 `loading`，`init` 的首次 refresh 与 resume
   刷新并发跑两路快照（每路一批 git 进程）。改为拦 `loading`，并新增 `refresh(silent=true)`：
   resume 时已有数据则不切 loading 占位（否则每次回前台整页闪一次空白）
7. **引擎 du 开销** → 从缓存 du 中拆出（合并超时会把可靠的缓存行一起弄没），并加 10 分钟
   进程内 TTL 缓存（引擎约 1.1GB、数十万文件，PRoot 下遍历成本高）

**性能审查 P2 处置**：MainActivity 淡入改用 `animateFloatAsState.finishedListener` 摘除图层
（替代硬编码 `delay(300)`，首帧重时不会提前摘除造成跳变）。

**性能审查确认无问题的项**：根层 `LocalContentColor` 不扩大重组范围（值随主题变化，与
ColorScheme 同源）；`LaunchedEffect(isScrollInProgress)` 不会反复启停抖动；其余 85 处静态
`contentColor` 无运行期代价。

**性能功耗纪律自查**：

- 不用常驻轮询；`LaunchedEffect` 均为一次性/状态驱动
- 淡入与滚动弱化改为布尔驱动挂载，动画值只在绘制期读取（避免每帧重组）
- 悬浮层 5 处独立图层合并为外层 1 处（图层数量下降）
- 引擎统计与容器缓存合并为一条 du（PRoot 遍历次数不增加）
- 存储扫描仍在 IO 协程，不占主线程
