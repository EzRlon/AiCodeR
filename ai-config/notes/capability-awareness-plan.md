# 能力自感知与路由机制（能力雷达）

> 用户原话（2026-10-14）：作为智能体，新版本增加了这么多新功能，我怎么才能知道——遇到可能的场景其实可以用自身的什么功能、哪些功能配合实现？以后任意情况，怎么知道自己已具备这些能力、遇到诉求可以自己调用并组合？

## 调研结论（已核实）

AI 的「能力自感知」= 每轮注入的上下文 + 可查的索引。现状 7 通道：
1. 工具 schema（每轮，覆盖全部内置 + MCP 工具）✓
2. 提示词片段 00~99（行为规则；只覆盖「有人写进去的」）⚠
3. 动态清单注入：技能/子代理/记忆/编队（99 片段变量机制）✓
4. 技能/记忆正文按需加载（loadSkill/memory read）✓
5. 官方文档 `~/.aicode/docs`（源自 docs-site/docs，构建同步；站/APP/AI 同源）——被动查询 ⚠
6. 消息类型瞬态标注 ✓
7. 项目规则 AGENTS.md ✓

抽查缺口（新功能 × 提示词关键词）：定时任务 / 交接 / 记忆图谱 / 笔记模式 / Web 预览 / 标注账本 / 检查点 / Hooks / 远程管理 / 测试包安装 → 提示词内均无感知件；而消息类型 / 自我改进 / 编队 / VNC → 有。即「碰运气，无纪律」。

## 方案（P0 已实施）

P0 三件套（零 Kotlin 代码）：
1. **能力地图** `AiCode/docs-site/docs/guide/capabilities.md`——单一知识源：五域（开发协作 / 知识沉淀 / 自动化 / 界面验证 / 外部设备）+ 组合菜谱 6 条 + 维护说明；随 syncAiDocs 进 APP 内置（AI 读 `~/.aicode/docs/guide/capabilities.md`）。
2. **能力雷达片段** `AiCode/app/src/main/assets/prompts/65-capabilities.md`——常驻速查（15 条场景）指向详图；编号 65 填补 60/70 之间空位；可被 prompts.custom 覆盖。
3. **纪律**：AGENTS.md 新增「能力感知」节——新功能必须带感知件（地图登记 + 如需则 65 更新）；qa 审查验证「AI 能答出」。
另：docs 站 sidebar「入门」组与 overview.md 已加入口。

## 验收进展

- qa 子代理独立审查已完成（2026-10-14）：链接 42/42、注入链路四环节、文档站构建、片段相关单测全部通过；发现 1 blocking（「远程管理」描述错误：实际管理手机外部存储而非工作区）与 6 条 non-blocking（编队入口应为顶栏、自我改进路径应含偏好设置、多模型限定语、菜谱 6 重写为真机验证闭环、webapp-testing 加「若已安装」、Hooks 补录）——**已全部修复并重建验证**。
- 待做（真机/新会话）：①确认 `~/.aicode/docs/guide/capabilities.md` 随版本释放存在；②全新会话问「你都能干什么」应给出结构化概览；③「帮我每天检查构建」应主动提定时任务入口。

## 维护指引（对施工会话）

- 新功能交付时：①地图对应域加一条（场景 → 能力 → 用法 → 入口）；②若会改变 AI 的建议/调用行为，加 65 速查行；③「规划中」的能力不上地图，上线后再登记。
