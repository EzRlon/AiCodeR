# QA 独立审查流程（已实施）

用户拍板的团队协作纪律，目的是补偿「同一上下文自审代码」的自确认偏差：

1. 项目级子代理 `qa` 定义在 `~/workspace/.aicode/agents/qa.md`：无写权限（白名单仅 readFile/list/search/Bash/terminal），全新上下文，按 AGENTS.md 注入项目规则。
2. `~/workspace/AGENTS.md` 已写强制规则：重大改动（新功能/重构/3 文件以上/关键修复）完成后必须派 qa 审查，轻微改动可豁免但需说明。
3. 派发时要交代：审查范围、构建/测试方式、期望产出格式（文件:行号 问题清单）。

注意：子代理定义在新会话才进入可派发清单；本会话若需演示可用默认通用子代理 + 同款提示词。qa 子代理可继承当前模型，用户之后可在 设置→子代理 换便宜模型。
## 子代理 qa 卡死教训（2026-10-19，已验证根因）
- 现象：qa 审五批次大改动时，进度句冻结于「审查批次 E」后数小时无输出、无报错、无残留进程（state 一直 running），只能 stop。
- 根因（按证据）：qa 创建 3 分钟后主线程启动了 19 分钟的完整打包（term-17），qa 按指令也自跑同一编译 → 并发抢 Gradle 项目锁；其自身 LLM 流式回合在 03:52:34 静默冻结——对应 network-switch-stream-hang 记忆的 App 层流卡死 bug（重网络活动 + 长回合窗口放大）。容器侧无工具层挂起痕迹（无进程、无 fifo、无 120s 超时残留）。
- 规则（后续所有 qa 派发遵守）：
  1. **主线程有 Gradle 构建在跑时，绝不派发 qa**；等构建结束再派。
  2. **qa 任务书里禁止它自跑 gradle/assemble**——编译验证由主线程负责并在派发前完成，qa 只读代码。
  3. 单次 qa 范围 ≤ 一个批次；多批次拆开派，避免超长单回合。
  4. 派发前在任务书写明「search 工具不可用，用 grep/find/readFile」（老坑防复发）。
