# 存储空间「推荐清理」增强设计（2026-10-22，基于现状探索）

> 现状基线：已有 8 类 CleanupKind 手动清理（勾选+确认弹窗+VACUUM+容器缓存白名单脚本），
> 本设计在其上叠加「推荐引擎」，不推翻现有通道。

## 一、推荐引擎（新组件 StorageCleanupAdvisor）

每条推荐必须能回答「为什么是垃圾」，三类判定：

### 分级策略
- **推荐级（默认勾选，一键即清）**：Caches、Logs、ContainerCaches（白名单五目录）、
  ToolOutput 超期产物（>30 天）、GeneratedImages 超期（>30 天无引用）
- **需确认级（默认不勾，逐条看过才删）**：
  - 孤儿检查点：`checkpoints/<id>/` 无 DB 会话记录对应
  - 孤儿识图会话 / 已删会话残留 ai-log
  - 无 profile 引用的容器镜像包（rootfs_images 旧包）
  - 超期检查点（会话 >N 天未活跃且检查点 >M 份保留近 2 份）
- **禁区（永不出现在推荐池）**：Workspaces 项目本体、OtherData、Apk、AI 配置目录、
  密钥、DataStore、容器 rootfs 本体——白名单写成显式常量（PROTECTED_PATHS），代码可审计。

### 孤儿检测（新增，现状为零）
- checkpoints 目录 vs Room 会话表对照
- ai-logs/session-*.log vs 会话表对照
- rootfs_images vs 容器 profile 列表对照
- tool-output / generated-images vs mtime 阈值
- （前置修复）删会话递归收集子代理会话（现仅一层，SessionUseCase.kt:55 自述），
  否则过期会话批量清理会留孤儿。

## 二、UI（存储页顶部新增「推荐清理」卡）

- 头部：「预计可释放 X（其中高置信 Y）」＋「扫描推荐」按钮
- 展开明细：每条 = 图标+名称+大小+**删除原因**（"30 天未使用"/"无对应会话"）+勾选框
- 推荐级默认勾选、需确认级默认不勾；底部「一键清除已选」→ 升级版确认弹窗
  （**逐条预览**将删清单，替换现有摘要式弹窗）→ 执行走现有 clean() 通道 → 完成后 VACUUM＋重新扫描
- 空态：「暂无推荐，存储很干净」正反馈

## 三、低频自动维护（性能功耗纪律内）

- WorkManager 每周一次低功耗扫描：只**更新推荐池数据**，绝不自动删除；
  可取消、结果缓存，打开存储页直接显示上次结论（与商店「秒出缓存」同思路）。

## 四、运行健康（进程/线程整洁，只读审计）

- 探索结论：现状健康（2 个 daemon 单线程 executor、appScope 无 GlobalScope、
  服务 onDestroy 完整、无泄漏实证）——**不做一键杀进程**（现有常驻皆有用途，杀了破坏功能）。
- 新增只读「运行健康」小节：常驻服务/周期任务/活跃扫描清单+状态，异常项（如连续失败的
  Worker）标红提示去处理；入口放存储页底部折叠组。

## 五、验收要点

- 白名单绝对性：构造密钥/工作区/配置目录路径，推荐池扫描 0 命中。
- 孤儿样例：手工造无引用 checkpoint 目录/镜像包，推荐池命中且删除后功能无损。
- 一键清除仅作用于勾选集；失败逐段兜底不中断其余项；VACUUM 后分类大小刷新。
- 每周任务不删任何东西、耗电可忽略（≤1 次/周、无网络）。
