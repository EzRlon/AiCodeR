# 用户审批偏好（2026-10-12 提出；2026-10-13 强化；2026-10-14 再次明确）

用户在 AiCode 中授权：**尽量直接执行工具调用，不要让他反复点「允许」**。
**2026-10-14 用户再次明确：「从现在开始，批准所有执行指令，不要在弹出窗口让我批准选择」**——执行层不再有任何征求批准的环节；也不要调用 askUserQuestion 让他做选择（除非方向性分叉且无法代选）。

## 执行纪律（2026-10-13 强化规则，优先级最高）
- **本项目工作区会话中：除「推进方向出现分叉选择」必须询问用户外，其余一切只要主 agent 判断为安全，均自动批准、直接执行，不再询问。**（安全裁量权归主 agent；方向分叉示例：多个合理方案需用户拍板、需求有歧义、可能偏离用户意图的取舍）
- 常规操作（读码、写文件、编译、测试、装依赖、派子代理、本地 git commit 等）一律直接做。
- 仍不“自动”的：不可逆/破坏性（删大量数据、覆盖未提交改动、git push/强推、发版打 tag）与共享状态变更——遇到时按主 agent 判断处理（能绕则绕，必要时一句话问清），它们不属于“安全指令”。
- 该偏好为跨项目通用（global），本项目会话执行最强化版。

## 交付阶段授权（2026-10-13）
- 用户明确批准「最后阶段的所有指令」：复核 → 汇报 → 最终构建 → 交付安装包的全程不再逐项询问/请求确认，直接执行到底（不可逆危险操作仍除外）。
- 提示用户自己可在 App 侧减少弹窗：
  1. 聊天输入框左上角模式按钮切到 **AUTO**（自动执行；仅灾难性 rm 与 Shizuku 宿主操作仍拦，可在设置里进一步关闭拦截）；
  2. BUILD 模式下弹审批时点**「始终允许」**，同类命令以后不再问（权限策略引擎会记忆模式）。
- 该偏好为跨项目通用（global）。
