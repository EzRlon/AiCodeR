# 工具授权体系升级 + 设备操作（真人模拟操作屏幕）设计方案（评审稿 v1，2026-10-14）

## 需求（用户要点）
- 「工具授权」里"没有任何规则"——要对齐曾研究过的开源项目（**Operit AI**）的丰富授权规则（其原话：三档工具权限「自动允许/每次询问/禁止」默认询问、无障碍+Shizuku+Root 三通道、PhoneAgent/AutoGLM 屏幕视觉操作、可为「UI 控制」单独指定模型）。
- 需要非常规权限（无障碍、通知等）以实现"真实完成真人模拟操作屏幕"。
- 流程要求：先评审 → 对比上版实现与本次重述的差异 → 重新择优设计。
- **硬要求（2026-10-14 追加）：每一个工具、每一条规则、每一张能力卡片、每一次授权弹窗，都必须配一目了然的中文解释它干什么用**；技术性原始字段（如 pattern）只能作为次要参考，不得裸展示。

## 一、评审：现状（已核实，带证据）
1. **引擎层（比表面印象深得多）**：`ToolPermissionPolicyEngine`（422 行）——
   - 三态裁决 ALLOW/DENY/ASK；顺序：灾难性删除防护（`elevate:true` 可提权一次性放行）→ DENY 优先 → PLAN 只读限制 → Shizuku 高危（一律弹窗、不可记忆）→ 不可静态判定命令必问 → 内置只读白名单直放 → 已记忆规则 → 默认询问；
   - 智能记忆：shell 按"程序名+子命令"前缀记（`git pull` 独立于 `git`）；rm 递归/通配不可记忆；hooks.json 写入不可记忆；改 Agent 配置类不可记忆；
   - 模式联动：PLAN 物理拦写、AUTO 全放行（灾难性删除与 Shizuku 除外；「禁用安全拦截」可在设置关闭防护）。
2. **规则持久化**：`PermissionRulesRepository`——全局 `filesDir/aicode/permissions.json`（AI 不可改）+ 项目级 `workspace/.aicode/permissions.json`（声明式、可 git 共享、AI 可改属有意设计）。规则形如 `Bash(git pull)`、`writeFile`。
3. **设置页（即你看到"没有任何规则"处）**：`PermissionsSettingsSection`——「安全防护」开关（禁用安全拦截，5 秒倒计时确认）+「当前项目/全局」两个**已保存规则**列表（左滑删、可提升为全局）+ 页脚说明。**规则只能由弹窗里"始终允许/拒绝"生长出来**；页面不能新建规则、无工具清单、无分档设置 → **你的感受准确：没有"预设规则体系"。**
4. **非常规权限现状**：已有——存储/通知/录音/安装包/电池豁免/**Shizuku（完整通道：ShizukuTool+Manager+ShellService+状态页）**；规划中——悬浮窗（悬浮球 B2-8，SYSTEM_ALERT_WINDOW）；**明确排除——无障碍/读屏/模拟操作**（笔记原话："不读屏、不模拟操作、无无障碍"；"不申请投屏、无障碍等系统级敏感权限"）；钉住——日历/屏幕时间类敏感权限不做。

## 二、对比：上版实现 vs 你的重述（差异清单）
| 维度 | 上版（已实现/已计划） | 你重述（对齐 Operit） | 差异 |
|---|---|---|---|
| 规则形态 | 算法默认 + 弹窗记忆规则；设置页只能看/删/提升 | 每工具三档（自动允许/每次询问/禁止），默认询问；分组管理 | 缺"预设分档 + 面向用户的规则编辑器" |
| 无障碍 | 明确排除（哲学边界） | 核心通道之一（无障碍+Shizuku+Root） | **方向性差异 → 需重新裁决** |
| 操作屏幕 | 无（映射预览刻意避开无障碍；悬浮球亦声明不模拟操作） | PhoneAgent/AutoGLM 屏幕视觉操作 + UI 控制模型 | 缺整个能力域 |
| Shizuku | 已有（逐次弹窗、不可记忆） | 三通道之一（ADB 级） | 底座已在，可增强（input/screencap 辅助） |
| 悬浮窗/通知 | 悬浮球已计划；通知已有（含直批） | 均已成熟落地 | 按计划推进即可 |
| 审计 | 无授权审计页（有 LLM 调用记录表） | 新授权系统含痕迹 | 缺审计面 |

**结论**：上版 = **引擎做得深、界面做得浅、能力边界做了排除**。本次两件事：①把深引擎"露出"为可配置的规则体系（吸收 Operit 三档+分组）；②**重新裁决"操作屏幕"边界**（用户点名引入无障碍，按授权约束设计）。

## 三、新方案（择优设计）

### A. 工具授权中心 2.0（无新权限，先行）
页面重构四区：
1. **工具规则（新）**：按类别分组（文件/终端/网络/浏览/设备与界面/媒体/子代理/配置）列出全部内置工具（图标+名称+**一目了然的中文说明**），每项**三档选择器：自动允许 / 每次询问 / 禁止**（档位行内可展开解释：自动允许=不再询问直接执行；每次询问=每次调用弹窗确认；禁止=直接拒绝并向 AI 说明原因）；默认：只读类=自动允许（沿用白名单优势）、写/系统类=每次询问。
2. **记忆规则（现有升级）**：标注来源（手动设置/弹窗记忆），保留左滑删/提升全局；**每条规则以中文解释为主行**（如「允许执行 git pull（拉取远端代码更新）」「禁止写入 .env 文件」），原始 pattern 降为次要小字（如 `Bash(git pull)`）；解释来源三层：①预置词条库（全部内置工具 + 常见命令前缀：git/npm/pip/rm/curl… 的常用子命令）；②模板兜底（任何规则都保证有中文，绝不裸显示英文 pattern）；③生僻 pattern 可选 AI 生成解释并缓存（标注来源）。
3. **授权档案（轻量）**：规则集合命名（预置「日常」「离开模式」「只读演示」），供定时任务/编队/子代理引用（对接 scheduled-ai-task-plan 的预授权清单）。
4. **授权记录（审计）**：最近 N 条（时间/工具/**中文动作摘要**/结果/批准方式/所属会话，点击跳会话；含通知直批记录）。
优先级定义（融合现引擎并归档）：内置安全防护（可 elevate）> 显式禁止 > PLAN 只读 > 显式规则/档案 > 智能默认（白名单/只读直放）> 询问；所有裁决记录原因。
兼容：permissions.json 格式与项目级 git 共享机制不变（档位为新增默认层，不迁移旧文件）。

### B. 设备操作能力包（"真人模拟操作屏幕"；**重大边界重裁决——需拍板**）
- **通道**：无障碍服务（主）；Shizuku（已有，增补点按/截屏辅助）；Root 不做。
- **工具类别「界面操作」**（默认全部"每次询问"）：读=节点树/查找元素/前台应用/截图；写=点击（元素/坐标）/长按/滑动/输入文本/按键（返回/主页/最近任务）/等待条件；**每个动作配中文说明**（如「点击屏幕上的某个按钮/图标」「在当前输入框输入文字」）。
- **安全设计（关键）**：
  1. 默认全关：无障碍需用户到系统设置手动开启（应用内引导）；
  2. **操作会话概念**：仅"界面操作"任务期间实际执行；期间通知栏常驻「AI 正在操作屏幕」+ 一键急停；配合悬浮球显示状态；
  3. 限速（操作间隔下限）+ 敏感界面保护（系统设置/支付/密码类界面默认停手并询问）；
  4. 离开模式/定时任务要操作屏幕必须单独勾「界面操作授权」（沿用预授权清单）；
  5. 全程审计。
- **进阶（v3）**：截图+视觉模型 PhoneAgent 式闭环 + 「UI 控制模型」专用设置（复用识图/压缩模型范式）。
- **合规**：仅自分发（不上 Play）；无障碍用途声明；Operit 为 LGPLv3、我 GPLv3——借鉴交互与架构，如其代码被引用需保留署名（LGPLv3→GPLv3 兼容）。

### C. 能力中心（对接 B2-5「工具与能力」归属框架）
- 设置侧新建「工具与能力」分组：工具授权（本篇）/ AI 工具箱 / 工作流 / 编队；非常规权限统一为**能力卡片**（用途+风险+引导开启+一键撤销+状态）：悬浮窗、无障碍、Shizuku、投屏（标注 v2 域内）、相机（B2）、通知（已有）。

### D. 分期
- **v1**（先行，无新权限）：授权中心 2.0（工具分档 + 记忆规则升级 + 审计记录；档案雏形）——B2-6「工具授权页改版」升级并入。
- **v2**：无障碍 UI 自动化 v1（服务+界面操作工具+急停/审计/限速）+ 悬浮球（B2-8）+ 能力中心。
- **v3**：PhoneAgent 视觉闭环、UI 控制模型、档案全接通（定时任务/编队/子代理）。

1. **工具档位存储**：DataStore Preferences（先例 EditorSettingsRepository）+ 独立仓库 `ToolPermissionTierRepository`；**不动 permissions.json 格式**（零兼容风险）。
