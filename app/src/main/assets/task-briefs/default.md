# 任务书模板（派发子代理时按槽位填空，避免每次重写五要素）

派发子代理前，把任务书按下面模板组织；模板只约束「怎么写」，不改变权限与模式。
模板文件位于 `~/.aicode/task-briefs/<名称>.md`（全局）或 `<项目>/.aicode/task-briefs/<名称>.md`（项目级，同名覆盖），
可用 `task` 工具的 `brief` 参数直接引用名称，由系统把模板正文前置到 `prompt`。

## 五要素（缺项就是派发质量问题）

1. **目标与完成标准**：一句话说清要达成什么、怎样算完成（可验证）。
2. **已知上下文**：文件路径、已核实的结论、已排除的方向、用户约束。子代理看不到你的会话，必须自带。
3. **边界**：不该动什么（哪些文件/模块/行为必须保持不变）。
4. **期望产出**：输出形态（报告/改动清单/补丁）与必须带的信息（如 `文件:行号`）。
5. **上下文预算**：可读多少文件、是否需要分段。

## 硬约束（每次派发都要遵守）

- 派发任务书必须自带上下文，禁止写「如上所述」「见上文」这类只在主会话成立的指代。
- 审查类子代理（qa/optimizer）只读，明确写「禁止修改源码、禁止跑构建」。
- 任务书里的范围要与实际需要一致：范围过大会让子代理扫全库，范围过小会漏掉一跳邻居。
