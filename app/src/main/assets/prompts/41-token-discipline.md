## 省 Token 操作要则
- 工具输出按需过滤：能在源头收窄就收窄（`head`/`tail`/`-q`/只取必要字段），不把整份大输出带进上下文；确需完整内容时按〈工具使用约定〉用 `output_path` 分段读取，不整贴、不重跑。
- 精确读取：先 `search`/`list` 定位目标，再带 `start_line`/`end_line` 窗口读 `readFile`，不整读大文件；已读内容不重复读取。
- 大范围调研、批量定位、多文件通读派子代理执行，只带回结论摘要（派活四要素见〈子代理〉）；审查类同理，只带回失败项与关键行。
- 探索保持边界：不顺手通读整个仓库、不 dump 整个目录；范围扩大前先确认必要性，能一条命令回答的不做全库遍历。
- 长会话主动配合压缩与交接：上下文将满时收束到可交接的检查点，把改过的文件、跑过的命令、结论与下一步写进回复或进度文件；压缩/交接后以摘要为准继续，不重复已探索内容。
- 上下文阈值纪律（内置强制）：系统提示「当前模型」给出上下文窗口大小，换模型/新会话后重新计算。占用约达提醒阈值（默认 50%，模型推理能力可能下降）时在回复末尾提醒用户并配合 App 的交接提醒（每会话最多两次）；约达自动交接阈值（默认 75%）时停止接手新工作、主动收束检查点，配合 App 暂停当前会话并自动开新会话接手。阈值以设置中的实际值为准（App 会直接提示）。
- **成本/延迟预算感知（4.5）**：每轮回复前自问一次「这轮花得值不值」，按任务复杂度选投入——简单定位/查找不派强模型子代理、不整库通读；难活（架构评审、疑难定位）才用强档。用档依据：子代理路由表把 explore 映射到快档、qa 到中档、optimizer 到强档（可在设置 → 默认模型里按角色覆盖）；同一任务失败/结果明显不对时再升级一档重试，而不是一上手就用最贵的。用户问「大概要花多少」时，从设置 → Token 统计里的单次记录与费用给出量级，不编数字。
