# 省 Token 操作纪律

目标：在保证任务质量的前提下，降低「完成整个任务」的总 token 消耗（tokens-per-task），而不是单次调用最少。以下纪律默认生效于所有工作；用户明确要求详尽输出时再放宽。

## 输出精简
- 结论先行：先给结果、决定与下一步，再按需补充依据；不写过程话术（「好的，我来…」）。
- 不复述：用户已知的、上文已说过的、工具已展示的内容不重复；代码与日志用文件链接引用，只贴必要片段。
- 按需展开：细节默认折叠或省略，用户追问再展开。

## 工具输出按需过滤
- 在源头收窄：命令优先用 `head`/`tail`/`-q`/`grep` 或只取必要字段的格式化参数，而不是整体输出后再挑选。
- 大输出先看 preview：结果含 `output_truncated` 与 `output_path` 时，先凭 preview 判断是否需要更多；确需时再 `readFile(path, start_line, end_line)` 分段读取目标区段，不整读、不重跑命令。
- 批量聚合：多文件/多命令的同类查询一次跑完并在命令内完成统计（`rg -c`、`wc -l`、`find -exec … +`），避免逐条往返。

## 精确读取
- 先定位后读取：用 `search` 定位符号/文本、用 `list` 看结构，再带 `start_line`/`end_line` 窗口读目标段落，不整读大文件。
- 不重复读：读过的内容在会话内直接引用；改文件用 `editFile` 精确替换，避免整文件重写与重读。
- 最小验证：能用一个搜索或一条命令回答的问题，不做全库遍历。

## 大任务交子代理，只带回摘要
- 全库扫描、批量定位、多文件通读、大范围调研交给子代理（`task`）执行：海量中间内容留在子代理的上下文里，本会话只接收结论——需要的字段与形式在派活时写清。
- 派活按四要素一次写全，背景信息用路径与链接引用，不重复粘贴。
- 审查与验证同理：让子代理跑构建/测试，只带回失败项与关键行。

## 长会话配合压缩与交接
- 上下文占用将满时，先收束到「可交接的检查点」：把关键信息（改过的文件、跑过的命令、结论与下一步）写进回复或进度文件，供压缩/交接保留。
- 压缩或交接后以摘要为准继续：不重复已完成的探索，缺口用搜索 + 窗口读取定点补回。
- 深入策略（何时压缩、保留什么、防过度压缩反噬）见 `context-compression` 技能。
