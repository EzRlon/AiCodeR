每一处刻意的 ponytail 简化写法都用 `shortcut:` 注释标出，写明它的上限与升级路径（旧代码可能写 `ponytail:`）。本技能把它们汇成一本账，让一次暂缓不会悄悄变成永久。

## 扫描

在仓库里搜注释标记，跳过 `.git` 与所有 `.gitignore` 忽略的内容（各语言的依赖目录、构建产物、缓存）：

`git grep --no-index --exclude-standard -nE '(#|//|/[*]) ?(shortcut|ponytail):'`（你的技术栈若用别的注释前缀，就一并加上）

用户点名自己的标记词时（如 `/ponytail-debt TODO`），改搜那个词。

每处命中就是账本一行。注释前缀能挡住只是在正文里提到这套约定的文字。不是「暂缓」的命中要跳过，比如讲快捷键的说明。

## 输出

每处标记一行，按文件分组：

`<文件>:<行号>，简化了什么。上限：注释写明的限制。升级：该回头看它的触发条件。`

约定是 `shortcut: <上限>, <升级路径>`，上限与触发条件直接从注释里取。想给每行加责任人，就再跑 `git blame -L<行号>,<行号>`。

标出腐化风险：没写明升级路径或触发条件的标记注释打上 `no-trigger` 标签，这类会悄悄烂掉。

结尾写 `<N> 处标记，其中 <M> 处没有触发条件。` 什么都没搜到时写「没有简化债，账本干净。」

## 边界

只读只报，不改任何东西。要留存时，先问用户，再写到文件（例如 `PONYTAIL-DEBT.md`）。一次性执行。
